# A11Y & i18n — accessibility and localization

> **Status: WIRED + ACTIVE.** The panel (`#a11y-panel`), locale switcher, live
> regions, palettes, remapping and all announcements below are live in the
> client — `index.html` ships the CSS/panel/ARIA, `hud.ts` localizes + announces,
> `main.ts` wires input/panel/palette, and both world renderers follow the
> colourblind-safe palette. What is *not* covered stays listed under Known gaps.

Client-side accessibility layer for AETHERFALL. Two modules:

| Module | Role |
|---|---|
| `client/src/a11y.ts` | Settings, live regions, keyboard nav, input remap, palettes |
| `client/src/i18n.ts` + `client/src/locales/*.ts` | 4 locales, fallback chain, server-prose translation |

Wired from `main.ts` (panel + input) and `hud.ts` (HUD strings, announcements).
CSS lives in `index.html` under the *ACCESSIBILITY* block; it is driven by
`data-a11y-*` attributes on `<html>` so themes apply without re-running JS.

Tests: `client/src/a11y.test.ts` + `client/src/i18n.test.ts` (`node:test`, headless).

## 1. Settings

All eight settings persist in `localStorage` under `af_a11y_v1` and apply live.
The panel is `#a11y-panel` (topbar ♿ button, or `Escape` to close it).

| Setting | Values | Effect |
|---|---|---|
| **Language** | `en` `tr` `de` `es` | Runtime switch; persisted in `af_locale_v1` |
| **High contrast** | on/off | `data-a11y-contrast="high"` → pure-black panels, white text, `filter: contrast()` on bars, 4px focus ring |
| **Colour palette** | default / deuteranopia / protanopia / tritanopia | `data-a11y-palette` + `--af-entity-*` / `--af-telegraph` CSS vars (minimap dots, HUD chrome) **and** both world renderers: `main.ts applyPalette()` pushes the preset into `CanvasRenderer.setEntityColors/setTelegraphColor` and `IsoRenderer.setEntityColors/setTelegraphColor`, so entity bodies + boss telegraph rings follow it live (local-player self marker stays green) |
| **Reduced motion** | on/off | `data-a11y-motion="reduced"` kills CSS animation/transition, the spinner and the damage vignette — **and** `shake()` + particle bursts in `main.ts` via `a11y.motionEnabled()` |
| **Text size** | 90 %–150 %, 5 % steps | `--af-scale` drives `html{font-size:calc(16px * var(--af-scale))}` plus HUD/settings/toast font sizes |
| **Screen reader announcements** | on/off | Gates the live-region queue entirely |
| **Movement keys** | WASD / arrows / IJKL / numpad | `data-a11y-scheme`; `readMove()` reads through `MOVE_KEYMAPS` |
| **Attack key** | any `KeyboardEvent.code` | Click the button, then press a key; `Escape` cancels |
| **Click to attack** | on/off | Off = keyboard-only attacking |
| **Hold to attack** | on/off | Re-queues a swing every 180 ms while the key/button is down |

Text scale is snapped to 5 % steps so the slider and the persisted value can
never disagree (`sanitizeSettings`). Every field is validated on read, so a
corrupt or partial blob degrades to defaults instead of poisoning the store.

## 2. Keyboard map

### Global

| Key | Action |
|---|---|
| `Tab` / `Shift+Tab` | Move between focusable widgets (HUD regions, panels, topbar) |
| `Escape` | Close the accessibility panel |
| `Enter` | Focus chat |
| `L` | Leaderboard |
| `M` | Mute |
| `E` | Editor paint (when the editor is active) |
| `?` — see skip link | First `Tab` press lands on **Skip to game** |
| Movement | `WASD` / arrows / `IJKL` / numpad `8 4 5 6` (configurable) |
| Attack | `Space` by default, fully rebindable |

### In the HUD (roving tabindex)

The HUD uses the ARIA **grid / toolbar** pattern: one `Tab` stop per region,
arrow keys to move *inside* it. This keeps the 20-slot inventory from costing 20
Tab presses.

| Key | Action |
|---|---|
| `↑ ↓ ← →` | Move focus within the HUD (left/right wrap, up/down clamp, 5-column grid rows) |
| `Home` / `End` | First / last item |
| `Enter` / `Space` | Activate the focused widget (native buttons/inputs handle their own) |
| `Tab` | Leave the HUD |

Focus rings use `:focus-visible` — visible for keyboard users, silent for mouse.

## 3. Screen reader behaviour

Two visually-hidden live regions are appended to `<body>` by `A11y.install()`:

- `#a11y-live-polite` — `role="status" aria-live="polite"` — ambient info
- `#a11y-live-assertive` — `role="alert" aria-live="assertive"` — life safety

`aria-atomic="true"` so each update reads as one sentence. Text is cleared then
re-set on the next frame so a repeated message re-announces.

### What is announced

| Event | Politeness | Source |
|---|---|---|
| Player join (`"<name> joined"`) | polite | `hud.addChat` |
| Mob death (`"<name> slain"`, `"has fallen"`) | polite | `hud.addKill` |
| Quest progress / completion | polite | `main.ts` `quest-progress` / `quest-complete` |
| Boss appeared | polite | `hud.setBosses` (once per boss, deduped) |
| Chat messages | polite | `hud.addChat` |
| Loot / inventory full / level up | polite | `main.ts` |
| **Boss telegraph** | **assertive** | `main.ts` `telegraph`, only when within `r + 6` |
| **Low health** (< 25 %) | **assertive** | `hud.setHp` → `a11y.reportHp` |
| **Your death / respawn** | **assertive** / polite | `main.ts` `showDeath` / `hideDeath` |

### AnnounceQueue

A polite/assertive priority queue (`AnnounceQueue`):

- **Assertive jumps the queue** — a boss telegraph is never stuck behind chat spam.
- **Identical messages coalesce** — a sustained low-HP state announces once, not
  at 10 Hz.
- **Backlog is capped** (20 per level, oldest dropped).
- **Locale switch clears pending polite messages** — a queued line in the old
  language mid-session would be confusing.
- **Low HP latches** — fires on the descending edge only, re-arms above 35 %,
  and is explicitly reset on respawn.

## 4. Localization

### Locales

`en` (source of truth), `tr`, `de`, `es` — **237 keys each**, covering HUD
strings, topbar/settings, overlays, the accessibility panel, announcements,
server prose (dialogue, quests, items, mobs, bosses, zones, telegraphs) and
client toasts/tutorial copy. `SERVER_TEXT_INDEX` holds **91** mapped English
source strings.

### Two layers of key completeness

1. **Compile time** — every locale is typed `Catalog = Record<MessageKey, string>`
   where `MessageKey = keyof typeof en`. A missing key in `tr.ts` is a **tsc error**.
2. **Runtime** — `auditLocale()` + `i18n.test.ts` re-check key coverage, extra
   keys, and **placeholder parity** (a translation may reword but must keep the
   same `{placeholders}`, or a value would silently vanish).

### Fallback chain

`tr → en`, `de → en`, `es → en`; English resolves to itself alone. A missing key
returns **the key itself**, never an empty string. `normalizeLocale('tr-TR') → 'tr'`;
an unsupported tag (`fr`) returns `null` so callers keep their current state.

### Server prose

The server speaks English on the wire, so `SERVER_TEXT_INDEX` (in
`locales/en.ts`) maps authored strings → catalog keys, and
`translateServerText()` localizes client-side:

1. **Exact match** — Elder Maren dialogue nodes, item/boss/mob/zone names, telegraph labels.
2. **Pattern rules** — templated lines: `"(.+) joined"`, `"(.+) slain"`,
   `"(.+) has fallen"`, `"Quest complete: (.+)"`, `"looted (.+)"`, the HUD quest
   title `"(.+) (n/m)"`, queue/kick lines. Captured groups are themselves
   localized, so `"Stone Golem has fallen"` → `"Steingolem ist gefallen"`
   (not a half-German string).
3. **Composed dialogue** — `@maren` replies arrive as
   `"<node text> 1. <label> 2. <label>"`; each part is translated separately.
4. **Pass through unchanged.**

### Rebuilding the index

Adding prose to `server/src/ai/dialogue.ts` or `content.ts` means adding a
`SERVER_TEXT_INDEX` entry plus the four catalog strings. A test asserts every
node/label/entity is indexed, so drift is caught.

## 6. Known gaps

Honest list of what is **not** covered:

1. **Player-authored chat is never translated.** Only server prose is indexed.
   Correct — translating what people typed would be wrong — but it means a
   German player sees whatever language their neighbours type.
2. **New server prose needs a manual index entry.** Nothing is auto-extracted
   from `server/src`. A new dialogue node ships untranslated until
   `SERVER_TEXT_INDEX` is updated (tests will not catch a *missing* authored
   string, only a missing *key*).
3. **The landing page below the fold is not localized.** The marketing hero,
   feature cards and download section stay English; only in-game chrome is
   translated. `index.html` static copy would need `data-i18n` attributes.
4. **No RTL support.** All four locales are LTR; the layout has no
   `dir="rtl"` handling.
5. **The visual world is not fully screen-reader navigable.** Announces events,
   but there is no spatial audio/tactile alternative for "where is the boss
   relative to me" — only the minimap (which is `role="img"` with a static
   label) and telegraph proximity.
6. **Minimap is `role="img"` with a static label.** It is not describable
   per-frame; announcing it would flood the live region at 4 Hz.
7. **Palette presets cover entity/telegraph colours only.** Entity bodies +
   telegraph rings follow the preset in both world renderers, the minimap and
   the HUD chrome — but terrain, zone tint and boss HP gradients still use the
   shipped colours.
8. **`IJKL` shadows `L`** (leaderboard). This is a genuine conflict, not a bug —
   `movementConflicts()` reports it and the panel shows a warning, but both
   cannot be bound simultaneously.
9. **Reduced motion does not stop WebGL-side animation.** Shake and particle
   bursts are suppressed, but renderer-internal interpolation continues.
10. **Colourblind palettes are not user-verified.** Hue-bucket separation and
    WCAG contrast are tested programmatically; no deuteranopia simulation was
    run against real screenshots.
11. **`lang` is set on `<html>`,** but per-element `lang` for mixed-language chat
    is not applied.
12. **No focus trap** on the death dialog — it is `aria-modal="true"` but focus
    can still Tab out (focus *is* moved to Respawn on death).
