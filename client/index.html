AETHERFALL

A browser MMO engine built from scratch — authoritative 20 Hz server, client prediction + interpolation, interest-culled snapshots, a hand-written binary protocol, and a from-scratch ECS. No engine. No networking library. Just sockets, math, and pixels. Enter a name and step through the gate.

✨ FEATURES

⚡ Authoritative netcode

20 Hz input, 10 Hz interest-filtered snapshots, ack-tracked reconcile + interpolation. Anti-cheat covers rate, burst, speed and teleport — every check exported to /metrics.

📉 Bandwidth as a feature

40 m interest cull with removed[] eviction, a cell-bucket index (O(N×E) → O(N+E)), serialize-once snapshots, and a negotiated binary protocol v2 at −93% bytes.

🧩 Custom ECS engine

Sparse-set ECS with a priority system scheduler, dynamic spatial hash, A* with corner-cut prevention, and deterministic biomes/zones/dungeons server and client both agree on.

🗺 Fog, bosses, day/night

Three-tier fog of war persisted per 8 m chunk, four bosses with server-sent telegraphs, a 120 s day/night cycle, minimap, kill feed and a 5-quest chain.

🧊 Two renderers

Three.js isometric 2.5D (instanced terrain, 2 draw calls) with a Canvas2D fallback that engages automatically on no WebGL or low FPS.

🤖 Prove it

Sharded bot swarm with deterministic profiles, chaos + anti-cheat probes, per-player CSV reports, replay recorder/scrubber and an offline benchmark dashboard.

🧬 Protocol v1 vs v2

60 moving entitiesbytes/framevs v1
v1 · JSON text (fallback: ?proto=1 / PROTO=1)7 755—
v2 · binary, deltas on (default)548−92.9%
v2 · binary, deltas off1 365−82.4%
v2 · idle shard38−99.5%

v2 is the default, negotiated over the existing v1 handshake (PROTO=1 / ?proto=1 forces the v1 fallback), so an old client talking to a new server keeps working. Most of the win is the encoding — varints, zigzag negatives, bit-packed field masks, per-frame string interning — not the delta trick. 200 moving entities costs 18.3 KB/s per player instead of 253 KB/s.

🧠 Authoritative

20 Hz server, 10 Hz interest-filtered snapshots, client prediction + reconciliation. The cheat surface is input timing and magnitude — five cheap checks, all counted in /metrics.

🗺 Interest-culled

40 m radius per viewer with removed[] eviction, backed by a cell-bucket index: O(N×E) → O(N+E). Bandwidth scales with density, not with CCU.

🧩 Built from scratch

Sparse-set ECS, spatial hash, A* with corner rules, deterministic worldgen, binary codec, shard router, bot harness. No game engine, no networking library.

⬇ DOWNLOAD / QUICKSTART

🚀 Run it locally

git clone https://github.com/Gourav-Shetty/AETHERFALL.git
cd AETHERFALL
npm install
npm run build --workspaces
npm run dev:server   # :8081 WS + :9090 metrics
npm run dev:client   # :5173 — open ?name=hero&autojoin=1

🤖 Living world in one line

SERVER=ws://localhost:8081 BOTS=20 node tools/bots/dist/index.js --duration 60 fills the arena with zero staging. Benchmarks at tools/capture/dashboard.html, 3-minute demo script at docs/DEMO.md.

Reproduce the headline number: node tools/bots/dist/index.js --bots 100 --duration 20, then curl -s localhost:9090/metrics | findstr aetherfall_tick.

No Docker needed for dev — SQLite + in-memory fallback. Compose is opt-in for Postgres/Prometheus.

Built with TypeScript · Three.js · ws · SQLite — portfolio piece, not a framework demo. MIT licensed. docs/CLIENT.md · ?autojoin=1 for one-click demo
